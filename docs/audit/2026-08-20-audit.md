# Security Audit — 2026-08-20

**Scope:** the P(-1) hardening pass on the initial Cyrius scaffold, before any feature work.
**Tree:** `src/` — 2 files, 34 lines. `cyrius init --language=none .` output plus the
`_agnostic_*` prefix corrections.
**Toolchain:** Cyrius 6.5.32 (pin matches installed wrapper — no drift).
**Method:** the eight-point process in `first-party-standards.md:65-72`, worked against the code
that exists rather than the code that is planned.

> ⚠ **This audit covers a scaffold, not a product.** Almost every finding is *not applicable* today
> and becomes applicable the moment the corresponding surface lands. Each N/A row therefore records
> **the milestone that re-opens it**, so this document is a checklist for M0–M9 rather than a
> one-time clearance. Re-run this pass before each minor cut, per `first-party-standards.md:817`.

---

## Result

**0 CRITICAL · 0 HIGH · 0 MEDIUM · 2 LOW** — both LOW findings are closed in this pass.

The scaffold has no external input, no buffers, no file handling, no subprocess execution, and
exactly one syscall family. There is nothing yet for the classic memory- and injection-class
findings to attach to; saying otherwise would be theatre.

---

## 1. Input validation

**N/A — no external input exists.**

`grep -rnE "args_|sys_read|recv|getenv" src/` → **0 matches**. The binary takes no arguments, reads
no stream, and consults no environment variable.

**Re-opens at:** M1 (HTTP surface). Every route handler accepts attacker-controlled bytes; the
`bayan_json_v_*` `*_from_value_a` allow-list idiom is the house pattern for bounding them
(`CYRIUS-PORT-BRIEF.md` §2). The oracle's failure mode to avoid is recorded in `ORACLE-AUDIT.md`
§3.3 — a request model and its translation layer disagreeing about which fields exist, so a
client-supplied `tasks` array was silently discarded by Pydantic's `extra='ignore'`.

## 2. Buffer safety

**N/A — no buffers declared.**

`grep -rnE "var [a-z_]+\[[0-9]+\]" src/` → **0 matches**.

The standard's rule is that `var buf[N]` means N **bytes**, not N entries, and every access must be
`< N`. The CI `security` job enforces the related ≥64KB stack-buffer ceiling automatically, so this
point is now gated rather than only audited.

**Re-opens at:** M1, first fixed-size request buffer.

## 3. Syscall review

**Clean — one syscall family, correct variant.**

Both `src/main.cyr:17` and `src/test.cyr:16` call `sys_exit_group`. That is the correct choice and
not the obvious one: bare `syscall(60, …)` (`SYS_EXIT`) ends only the **calling thread**, so a
program that has spawned a worker hangs on exit instead of terminating. The scaffold's own comment
records this. The CI security scan greps for `syscall(59|60` precisely to stop the wrong variant
reappearing.

Return values: `sys_exit_group` does not return, so there is no unchecked return here.

**Re-opens at:** M1 (sockets via sandhi), M4 (patra file I/O).

## 4. Pointer validation

**N/A — no pointer arithmetic on untrusted data.**

No `load64`/`store64` against externally-derived offsets exists in `src/`. Cyrius is fully manual
here (everything is one 64-bit word; `lib/alloc.cyr` is a bump allocator with **no `free()`**), so
this becomes one of the highest-value audit points once real data structures land.

**Re-opens at:** M1. The specific hazard to watch, from `CYRIUS-PORT-BRIEF.md` §1.1, is that arena
exhaustion returns 0 and a `Str` of 0 is indistinguishable from a valid one — there is no option
type and no error channel through the `_a` families, so it flows on and the first dereference
crashes. That is why the per-request arena uses a SPILL policy.

## 5. Command injection

**N/A — no subprocess execution.**

`grep -rncE "sys_system|exec_cmd" src/` → **0 in both files**. Now permanently gated: the CI
security job fails on any `sys_system(` in `src/`.

**Re-opens at:** M6 (tool execution) — and the answer there is already decided. Per
`first-party-standards.md:76`, *"kavach owns the sandbox, not the application. Applications never
manage their own security boundaries."* Agnostic must delegate to kavach's sandbox tiers rather
than hand-rolling an rlimit subprocess, which is what the Python oracle did
(`python-port/agents/tool_sandbox.py`).

## 6. Path traversal

**N/A — no file path handling.**

`grep -rnE "fs_open|sys_open|file_" src/` → **0 matches**.

**Re-opens at:** M4 (report/artefact storage). Any path derived from a job definition, a tenant id,
or a report name needs `../` rejection before it reaches the filesystem.

## 7. Known CVE review

**Clean — no third-party dependency surface.**

`[deps]` declares only folded stdlib modules: `string, fmt, alloc, io, vec, str, syscalls, assert,
bench`. There are **no `[deps.NAME]` git dependencies** and therefore no `cyrius.lock` — which is
the documented default (`first-party-standards.md:135`), not an omission.

Two ecosystem CVE-class items are already reflected in this repo's configuration:

- **CVE-21** — both workflows pin `actions/checkout` and `softprops/action-gh-release` by commit
  SHA rather than tag.
- **sigil RSA/PSS verify bypass**, closed across sigil 3.12.3–3.12.6. Not yet reachable here, but
  it becomes reachable the moment `[deps.sigil]` lands for API-key hashing and webhook HMACs. The
  invariant is that any `[deps.sigil]` tag must equal what the pinned toolchain folds — verified by
  `head -3 ~/.cyrius/versions/<pin>/lib/sigil.cyr`, currently **3.12.9**.

**Re-opens at:** every dependency addition, and at every toolchain pin bump.

## 8. Findings

### LOW-1 — unprefixed globals in the generated harnesses *(closed in this pass)*

`cyrius init` emitted `var r = main();` in `tests/agnostic.bcyr` and `tests/agnostic.fcyr`, and
`var exit_code = main();` in `tests/agnostic.tcyr`. Cyrius has one flat symbol table with
last-definition-wins, and a test binary links **all** of `lib/`, which exports roughly 180
unprefixed names.

*Verified not currently exploitable*: `grep -rhE "^var (r|exit_code|f)\b" lib/*.cyr` → 0 matches,
and `lib/` declares no single-letter globals at all. So this was latent, not live — but the
dependency set is about to grow by six packages, and the same class already caused a real incident
upstream (an audit on 2026-07-31 found four duplicated enum constants, three with *different*
values, three of them struct sizes passed straight to `alloc()`).

**Fix applied:** renamed to `_agnostic_bench_exit_code`, `_agnostic_fuzz_exit_code`,
`_agnostic_test_exit_code`. `src/main.cyr`'s equivalent was corrected during scaffolding and is
enforced by `scripts/check-symbols.sh`, which is a CI gate.

**Residual:** `check-symbols.sh` scans `src/` only, so `tests/` is convention rather than gate.
Acceptable while `tests/` is three files; revisit if the suite grows past a handful.

### LOW-2 — exit-code masking in the fuzz and bench harnesses *(accepted, documented)*

A wait status is 8 bits. `tests/agnostic.tcyr` clamps correctly — `if (… > 0) { … = 1; }` — because
`assert_summary()` returns a raw failure **count**, and exactly 256/512/768 failures would otherwise
exit 0 and score PASS. The `.bcyr` and `.fcyr` harnesses do not clamp.

*Assessed as acceptable*: neither returns a failure count. `main()` in both returns a literal `0`,
so there is no path to a value ≥256 today.

**Action:** no code change. Recorded here so that the first harness returning a count adds the
clamp — the guard is only load-bearing once the value is derived rather than literal.
