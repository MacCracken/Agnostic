# Security Audit — M1 (HTTP foundation)

**Scope:** `src/` after M1 — 12 files, 129 top-level definitions. The milestone where untrusted
bytes first reach a buffer, so it re-opens audit points 1, 2, 3 and 4 simultaneously (predicted in
`2026-08-20-audit.md`).
**Toolchain:** Cyrius 6.5.32, pin matches wrapper.
**Method:** the eight-point process in `first-party-standards.md:65-72`, plus live exercise of the
running binary over a socket.

## 1. Input validation — **now applicable, covered**

Entry points: `src/server/serve.cyr` (5 sandhi accessor sites) and `src/trace.cyr` (2). Everything
attacker-controlled arrives through those.

- **Method** — mapped through `agnostic_method_from`; anything unrecognised becomes
  `AGNOSTIC_METHOD_NONE`, which the route table can never match. An exotic verb 404s rather than
  being treated as GET.
- **Path** — query and fragment stripped before matching; `:name` binds exactly one non-empty
  segment; a trailing separator is a distinct path. Verified over the wire.
- **Body size** — checked **before** routing, so a large body aimed at a bad path is rejected on
  size rather than parsed to discover it has nowhere to go. Bound is `AGNOSTIC_MAX_BODY_BYTES`,
  1 MiB by default, and also set as sandhi's `max_request`.
- **Config** — every value strictly parsed; a malformed one **refuses to start** rather than
  silently defaulting. Exercised: `AGNOSTIC_PORT=99999` and `AGNOSTIC_LOG_LEVEL=loud` both refuse;
  `AGNOSTIC_PORT=0` starts, because 0 is a legal port.
- **JSON** — `src/http/codec.cyr` decodes against an allow-list; an unlisted key is a 422 naming the
  field. No request body route exists yet, so this is not yet on a live path.

⚠ **`traceparent` is echoed into logs.** `agnostic_trace_begin_a` accepts an inbound header when it
is exactly 55 bytes and the log formatter escapes it (quotes, backslashes, newlines, `\u00XX`
controls) — so it cannot break the JSON line or forge members. The length check is a shape check,
not a syntax check: a 55-byte value of arbitrary bytes is accepted and logged escaped. Judged
acceptable — it is bounded, escaped, and never interpreted.

## 2. Buffer safety — **now applicable, bounded**

Five fixed buffers, all bounded by construction:

| Site | Size | Bound |
|---|---|---|
| `log.cyr:210` | 4096 | Every write goes through `_agnostic_log_put`, which returns unchanged at `pos >= cap`. The formatter clamps its return to `cap`. Tested with an 8192-byte message: truncates, never overruns. |
| `log.cyr:130`, `:239` | 24 | i64 decimal is at most 20 digits plus sign. |
| `serve.cyr:70` | 128 | `sys_read` is passed the literal 128. |
| `serve.cyr:84` | 8 | One sigset word, written by a single `store64`. |

4096 is PIPE_BUF, so a log line is one atomic `write(2)` and concurrent workers cannot interleave
halves of two lines.

## 3. Syscall review — **now applicable, clean**

Five syscalls, all checked:

- `sys_exit_group` ×2 — correct variant; bare `syscall(60)` ends only the calling thread and would
  hang a process with workers.
- `sys_sigprocmask` — return checked (`< 0` aborts signal setup).
- `sys_signalfd` — return checked.
- `sys_read` — return checked (`n > 0` before logging).
- `sys_write` — fd 2, length from the clamped formatter.

⚠ **Ordering is load-bearing**: `sigprocmask` runs before any worker is spawned, because the mask is
inherited. Blocking after would let a signal be delivered to an arbitrary worker and kill it
mid-request.

## 4. Pointer validation — **now applicable, covered**

The sharp hazard in this codebase, and the one M1 was gated on:

- **Arena exhaustion returns 0**, and a `Str` of 0 is indistinguishable from a valid one — no option
  type, no error channel through the `_a` families. Every constructor returns 0 rather than a
  half-built record; tested for `agnostic_trace_generate_a`, `agnostic_response_json_a` and
  `agnostic_response_text_a` against deliberately tiny arenas.
- **SPILL** is applied to sandhi's request arena, so an oversized response degrades to the global
  bump instead of faulting.
- **A null response is 500**, not a fault — `agnostic_response_status(0)` returns `HTTP_INTERNAL`, so
  the serve adapter needs no special case, and a render failure sends 500 rather than an empty 200
  that a client would read as success.
- **cstring vs `Str`** — sandhi's accessors return NUL-terminated cstrings. Every one is wrapped
  with `str_from_a` before use. Passing a raw pointer where a `Str` is expected reads the pointer as
  a `Str` header, and every downstream length is garbage.

## 8. Findings

### MEDIUM-1 — no request rate limiting *(accepted, bounded, scheduled)*

Nothing limits request rate or concurrent connections beyond sandhi's `max_conns` worker pool
(16 by default). An unauthenticated client can occupy all workers with slow or repeated requests.

*Bounded, not unbounded*: `max_conns` caps concurrency, `idle_ms` (30 s) reaps slow connections,
`max_request` caps body size, and every M1 handler is O(1) with no I/O — `/health` and `/ready`
allocate a few hundred bytes and return.

**Deliberately deferred to M5**, where it belongs with authentication. The reason is recorded in the
M5 plan: Argon2id at ~244 ms makes login a request-amplification lever (measured in SecureYeoman's
probe: 8 concurrent attempts took `GET /health` from 6 ms to 942 ms; ~40 wedged a 4-worker pool).
The mitigation must shed **before** the KDF runs, so it is designed with the credential path rather
than bolted on now against handlers that cost nothing.

### LOW-1 — `traceparent` accepted on shape, not syntax *(accepted, documented)*

See point 1. Bounded at 55 bytes and escaped on output. A stricter parse (hex digits, version `00`,
non-zero ids) would be more correct and is worth doing when a real distributed trace consumer
exists; today it would reject nothing that causes harm.

### LOW-2 — no `Server` header suppression *(accepted)*

sandhi controls response headers. Not currently a disclosure of anything version-specific.

## Addendum — 2026-08-21: point 7 re-opened by the first dependency

The finding above ("still no `[deps.NAME]` git dependencies and therefore no lockfile") was accurate
when written and is now **superseded**, recorded here rather than edited in place so the record
stands.

`[deps.agnosai]` landed at **2.0.4**. There is now a `cyrius.lock` with **115 entries**
(`deps --verify` 115/0), and `lib/` holds 7 transitively-provisioned libraries alongside the 101
toolchain files — `kavach`, `ai-hwaccel`, `bote-core`, `libro`, `majra`, `tyche`, `agnosai`.

**This changed the answer to point 7 materially**, and not in the direction the original entry
implies. The first thing the dependency set brought was a memory-safety defect: kavach and
ai-hwaccel both defined `var BACKEND_COUNT` (10 and 18), Cyrius resolves duplicates
last-definition-wins and is **silent** for `var`, so kavach's `_backend_fp` bounds check ran against
18 over a 10-slot table and admitted ids that index past `_backend_table[320]` into a `fncall2`.

Severity in this repo **would have been HIGH**: an out-of-range backend id yields a wild function
pointer, and non-zero `.bss` defeats the `fp == 0` check. It is closed — kavach 3.11.15 and
ai-hwaccel 2.3.18 renamed to `KAVACH_BACKEND_COUNT` / `AIHW_BACKEND_COUNT`, folded by agnosai 2.0.4
— and verified in this compile unit by `tests/deps_symbols.tcyr` (14 assertions, three mutants
killed).

### What this says about the review process, which matters more than the instance

Nothing in the toolchain or this repo's gates could have caught it. The compiler warns on a
duplicate `fn` and is silent on a duplicate `var`; `check-symbols.sh` — here and in every sibling —
scans `src/` only. A `lib/`↔`lib/` collision is invisible to both at once. Point 7 as written asks
about *known CVEs*; the real exposure at this dep set was a **symbol collision**, which no CVE feed
would ever carry.

A full sweep at the current dep set found no remaining silent collision: of 3,040 top-level `var`s
across `lib/`, only `AT_FDCWD` and `TASK_SIZE` differ across files, and both are platform-variant
families where one variant is prepended per target. `HTTP_OK`/`HTTP_NOT_FOUND` are defined by both
`http.cyr` and `sandhi.cyr` at identical values — redundant, not a defect.

⚠ **Open, accepted, and visible**: 20 duplicate-`fn` warnings at build — kavach ↔ sigil share the
`syserr_*` family and seven `agnosys_*` helpers; `libro` and `majra` both define `_sub_new`. These
are upstream and they announce themselves at every build, which is the whole difference between them
and the `var` case.

⚠ **Latent**: kavach's enum *members* (`PROCESS`, `WASM`, `OCI`, `NOOP`) are generic and unprefixed.
A Cyrius enum qualifier is cosmetic — `Backend.WASM` and `KavachBackend.WASM` both resolve to member
`WASM` — so the upstream type rename does not protect them. Pinned in `tests/deps_symbols.tcyr`.

**Next pass unchanged: before M5.** M2 will grow the dependency surface considerably, so point 7
should be re-run with the `lib/`-wide `var` sweep as a standing step, not as a one-off.
